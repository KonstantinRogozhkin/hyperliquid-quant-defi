# Метамодель Hyperliquid с измеренными издержками исполнения

Дата: 2026-11-26. Issue: #8. Продолжение [hl_alo_fill_portfolio_coins.md](hl_alo_fill_portfolio_coins.md) и [hl_colab_multifamily_metamodel.md](../2026-11-25/hl_colab_multifamily_metamodel.md). Только исследование на публичных данных, ордеров нет.

## Постановка

- Тот же замороженный бандл (`/tmp/hl-meta-20261125/dataset_bundle.parquet`: 70 монет, 180 дней), тот же реестр из 48 гипотез, те же Dev-фолды и Holdout 45 дней, тот же гейт отбора (`dev_sharpe >= 0.5`, `dev_stressed_sharpe >= 0`, плюсовые Dev-фолды `>= 80%`, корреляция `< 0.5`, не больше 2 гипотез на семейство). Код — `main` после PR #13–#15.
- Меняются только издержки на единицу оборота (новые флаги `run_hl_colab_shard.py`: `--hl-bps`, `--cross-venue-bps` и их стресс-версии):

| Сценарий | HL однобиржевая | Кросс-биржевая (HL + CEX) | Стресс (+2 б.п.) |
|---|---|---|---|
| Прежний (бэктест) | 1.5 | 3.5 | 3.5 / 5.5 |
| Промежуточный | 3.5 | 5.5 | 5.5 / 7.5 |
| **Измеренный** | **5.0** | **7.0** | **7.0 / 9.0** |

  `5.0 б.п.` — медианная стоимость пассивной ALO-сделки на 19 монетах портфеля (fill, adverse selection, добор тейкером). Для CEX-ноги оставлена мейкерская комиссия `2.0 б.п.`: её исполнение не измерялось.
- Контроль: прогон с прежними издержками на этом коде совпадает с пересчётом после PR #13 до знака (отбор `xs_rev_L24_r12`, `carry_best_cex_L168_in5`, `xs_mom_L72_r24`; `shrinkage_sharpe` Holdout `+32.18% / Sh 3.11`).

## Результат

**При измеренных издержках гейт проходит одна гипотеза — `carry_best_cex_L168_in5`.** Так же и при промежуточных `3.5 б.п.` Метамодель вырождается в один carry-слой:

| Сценарий | Отбор | Dev 75d (APR / Sh / DD) | Holdout 45d (APR / Sh / DD) | Holdout Ex-`INIT` (APR / Sh) | Ex-`INIT` стресс |
|---|---|---|---|---|---|
| Прежний (1.5 / 3.5) | 3 гипотезы | +23.62% / 2.29 / −2.91% | +32.18% / 3.11 / −2.89% | +22.37% / 2.33 | +12.21% / 1.27 |
| Промежуточный (3.5 / 5.5) | 1: `carry_best_cex_L168_in5` | +2.74% / 1.03 / −0.42% | +34.81% / 4.66 / −2.00% | +0.16% / 0.08 | −0.54% / −0.28 |
| **Измеренный (5.0 / 7.0)** | 1: `carry_best_cex_L168_in5` | **+2.12% / 0.79 / −0.43%** | **+34.39% / 4.60 / −2.00%** | **−0.37% / −0.19** | **−1.07% / −0.54** |

Весь результат на Holdout — одна монета `INIT`. Без неё отобранная модель на Holdout в нуле.

**Почему отсеиваются остальные** (измеренные издержки; топ по Dev Sharpe):

| Гипотеза | Dev (APR / Sh) | Dev стресс Sh | Плюсовые фолды | Holdout (APR / Sh) | Почему не прошла |

| `xs_rev_fundblend_L24` | +31.13% / 1.04 | 0.42 | 2 из 5 | +86.71% / 3.19 | фолды |
| `carry_best_cex_L168_in5` | +2.12% / 0.79 | 0.48 | 4 из 5 | +34.39% / 4.60 | **прошла** |
| `xs_mom_L168_r24` | +19.27% / 0.67 | 0.42 | 2 из 5 | −156.08% / −5.84 | фолды |

Плюсовой Dev Sharpe при измеренных издержках у 10 гипотез из 48, при прежних — у большинства.

## Выводы

- **При реалистичном исполнении на HL устойчивого преимущества по этому протоколу нет.** Однобиржевые семейства (реверсия, моментум, funding-сигналы на HL) держатся на обороте и при `3.5–5 б.п.` на сделку теряют устойчивость по фолдам. Funding-carry проходит гейт, но без выброса `INIT` на Holdout не зарабатывает.
- `xs_rev_L24_r12` и `xs_rev_fundblend_L24` на Holdout по-прежнему в плюсе (`+25%` и `+87%`), но на Dev плюсовые только 2 фолда из 5. Включить их по результату Holdout значило бы подогнать модель под Holdout.
- Текущие замороженные веса paper-трекера (`carry_L168 0.400`, `xs_rev 0.379`, `xs_mom 0.221`) получены при издержках `1.5 б.п.` и при измеренных издержках не подтверждаются: `xs_mom_L72_r24` даже на Dev почти в нуле (`+3.04% / Sh 0.11`), а на Holdout в минусе.
- Paper-трекер по-прежнему считает издержки как `1.5 + 0.5 × спред` и завышает результат (за первые 6 тиков примерно на `$62` из `$81` прибыли).

## Ограничения

- Стоимость `5.0 б.п.` измерена за один ночной час (03–04 UTC) на текущих монетах портфеля и применена ко всем монетам и ко всем слоям одинаково. У ликвидных монет она ниже (`HYPE −3.1`, `ZEC −3.3`), у малоликвидных выше; медленный carry может ждать исполнения дольше 60 с и платить меньше.
- Издержки CEX-ноги не измерялись.
- Survivorship bias, закрытия 1h, отсутствие модели маржи и перевода залога — как в исходном отчёте.

## Что дальше

1. **Снизить оборот, а не подбирать параметры:** добавить в реестр медленные версии `xs_rev` / `xs_rev_fundblend` (ребаланс 24–48 ч, сглаживание весов, порог на изменение позиции) и прогнать при измеренных издержках с тем же гейтом.
2. **Издержки по монете:** подставлять измеренную стоимость сделки для каждой монеты и ограничить вселенную монетами, где пассивное исполнение работает (fill `>= 80%`).
3. **Paper-трекер:** перевести учёт издержек на измеренные значения, чтобы журнал не завышал результат.
